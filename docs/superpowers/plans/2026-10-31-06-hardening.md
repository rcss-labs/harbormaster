# Harbormaster 06: Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the product built in plans 01–05 deployable and operable: Terraform modules for Harbormaster itself and for the per-account access role, a pinned multi-stage container image, security headers, a token-protected `/metrics` endpoint, a verified ECS API budget with a soak test at the target estate, brand assets, docs/licences, a full role-based Playwright suite and a release build target.

**Architecture:** Nothing here adds product features. Go changes are thin and additive: one outermost HTTP middleware for headers, one `internal/telemetry` package with a hand-written Prometheus text writer fed by an AWS SDK middleware and two poller hooks, one `/metrics` handler. Infrastructure lives in `terraform/modules/*` (validated locally with `fmt`/`validate` only; plans and applies run in TerraDuckTel) and in a three-stage `Dockerfile` whose final image is distroless, non-root and pinned by digest. Verification of scale claims is a tagged Go soak test over `awsx/fake` scaled to 20 account×region loops.

**Tech Stack:** Go 1.26, AWS SDK for Go v2 (`smithy-go` middleware), pgx v5, PostgreSQL 16, React 19 + Vite + Playwright, Terraform ≥ 1.5 with the AWS provider, Docker (BuildKit), distroless static.

**Spec:** [`docs/design/2026-10-31-harbormaster-design.md`](../../design/2026-10-31-harbormaster-design.md) — §5.3 (budget, back-off, `/metrics`), §7.5 (Terraform interplay), §11 (AWS access and deployment), §14.1 (brand), §15 (security), §16 (testing), §17 phase 6, §18 (licence).
**Conventions:** [`2026-10-31-00-conventions.md`](2026-10-31-00-conventions.md) applies in full.

## Review Focus

Inputs the spec implies but no feature plan tests; each has its pinning test in the task named.

1. `/metrics` reached when `HM_METRICS_TOKEN` is unset — must answer 404, not expose poller stats to the ALB's whole audience (Task 4, `TestMetricsHandler_DisabledWithoutToken`).

5. A non-admin who deep-links to `/admin/users` or calls `GET /api/users` directly must get the no-access screen and a `403 forbidden` JSON body, never data (Task 19, `admin routes refuse omer`).

Header values (exact):

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'` |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `same-origin` |

Why these: fonts are self-hosted (01 Task 24) so "self + fonts" collapses to `'self'`; `style-src` needs `'unsafe-inline'` because xterm.js's DOM renderer injects `<style>` elements and React sets `style=` attributes in chart panels — scripts stay strictly `'self'`. HSTS is sent on every response; browsers ignore it over plain HTTP so `make run` on `127.0.0.1` is unaffected. `connect-src 'self'` covers same-origin `wss:` in CSP Level 3 browsers (Chromium, Firefox, Safari ≥ 15.4).

**Interfaces:**
- Consumes: Task 2 `Config.MetricsToken`; Task 3 `telemetry.Registry`.
- Produces: `func MetricsHandler(token string, reg *telemetry.Registry) http.Handler` in `api`; `func TelemetryMiddleware(account, region string, reg *telemetry.Registry) func(*middleware.Stack) error` in `awsx` (`middleware` = `github.com/aws/smithy-go/middleware`).

Behaviour of `MetricsHandler`: `token == ""` → `404` with the standard JSON error (`not_found`); missing/wrong `Authorization: Bearer <token>` → `401` `unauthenticated` (compare with `crypto/subtle.ConstantTimeCompare`); otherwise `200`, `Content-Type: text/plain; version=0.0.4; charset=utf-8`, body from `WritePrometheus`. Not subject to the session cookie, CSRF or ETag middleware.

Behaviour of `TelemetryMiddleware`: a Finalize-step middleware that, after the next handler returns, calls `reg.CountAWSCall(account, region, awsmiddleware.GetServiceID(ctx), awsmiddleware.GetOperationName(ctx), result)` with `result` = `"throttled"` when `awsx.IsThrottle(err)`, `"error"` for any other error, else `"ok"`. Counting happens once per logical call, after SDK retries (Finalize wraps the retry loop's outside; use the position `middleware.Before` on the Finalize step so retries are inside).
