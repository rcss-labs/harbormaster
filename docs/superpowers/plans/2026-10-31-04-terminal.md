# Harbormaster 04: Terminal (ECS Exec bridge) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser terminal into a running ECS task: the server calls `ecs:ExecuteCommand`, speaks the SSM Session Manager data-channel protocol to `ssmmessages`, and bridges bytes to xterm.js over a Harbormaster WebSocket, with permission checks, limits and operations-log entries.

**Architecture:** `internal/execbridge` is a from-source port of the parts of `github.com/aws/session-manager-plugin` (Apache-2.0) that a shell session needs: binary message codec, data channel (sequence numbers, acknowledgements, retransmission, reorder buffer, handshake), a WebSocket frame connection, and a `Session` that owns one ECS Exec session end to end (open, bridge, idle/max timers, `ssm:TerminateSession`). `internal/api` exposes `WS /api/tasks/{taskId}/exec` and `GET /api/tasks/{taskId}/exec-targets`; the React Terminal tab drives xterm.js. A fake SSM data-channel server in `internal/awsx/fake` lets every test and `make run --fake-aws` work without AWS.

**Tech Stack:** Go 1.26, AWS SDK for Go v2 (`service/ecs`, `service/ssm`, `aws/signer/v4`), `github.com/coder/websocket`, `github.com/google/uuid`, `log/slog`; React 19 + TypeScript, `@xterm/xterm` 5.5.0, `@xterm/addon-fit` 0.10.0, TanStack Query v5, Vitest, Playwright.

**Spec:** [`docs/design/2026-10-31-harbormaster-design.md`](../../design/2026-10-31-harbormaster-design.md) §9 (core), §6.4 Terminal tab, §6.5, §3 action T, §11.2, §13, §16, §18. Conventions: [`2026-10-31-00-conventions.md`](2026-10-31-00-conventions.md). Mockup: [`docs/design/mockup/index.html`](../../design/mockup/index.html) lines 254–259 (`.term` styles), 779 (`lockPanel`), 1391–1431 (`sTerminal`, `termRun`), 2022–2035 (`exec-task`, `term-connect`, `term-disconnect`); screenshot [`service-terminal.png`](../../design/screens/service-terminal.png).

**Suggested implementer tiers:** Task 1 Sonnet · Task 2 Sonnet · Task 3 Sonnet · Task 4 Sonnet · Task 5 Sonnet · Task 6 Sonnet · Task 7 Sonnet · Task 8 Sonnet · Task 9 Haiku · Task 10 Haiku. ## Review Focus

1. **Paste of several KB into the terminal** — a person expects it to arrive in order and complete; input_stream_data messages must be chunked at 1024 bytes with consecutive sequence numbers, not one oversize frame. Test: Task 2 `TestDataChannel_SendInput_ChunksAt1024`.
2. **Typing while SSM is slow to acknowledge** — upstream drops the oldest unacknowledged message when its buffer (10 000) is full; a person expects keystrokes never to be silently lost, so `SendInput` must block (apply backpressure) instead. Test: Task 2 `TestDataChannel_SendInput_BlocksWhenOutgoingBufferFull`.
3. **xterm's fit addon fires a resize before the handshake completes** — a size message sent before the handshake confuses the agent; the latest size must be queued and sent once, right after `HandshakeComplete`. Test: Task 5 `TestSession_ResizeBeforeHandshake_IsSentAfterHandshake`.
4. **The ssmmessages socket drops mid-session** (network, token expiry, task stopped) — a person expects a clear "closed: …" line, `TerminateSession` still called, and the browser socket closed, not a hung terminal. Test: Task 5 `TestSession_UpstreamSocketDrop_ClosesWithSSMError`.
5. **A crafted `command=` query** (`/bin/sh; curl …`, `sh -c …`) — the server must accept only the two listed commands and answer `invalid`, never pass user text to `ecs:ExecuteCommand`. Test: Task 7 `TestExecWS_RejectsCommandOutsideAllowlist`.

**Protocol facts (source: `src/message/clientmessage.go`, `src/message/messageparser.go`, `src/message/handshakemessage.go` on `mainline`):**

Binary header, all integers big-endian, total length = `HeaderLength + 4 + PayloadLength`:

| Offset | Len | Field | Encoding |
|---|---|---|---|
| 0 | 4 | HL (header length) | uint32; always written as **116** (= offset of PayloadLength) |
| 4 | 32 | MessageType | ASCII, right-padded with spaces (`' '`); on read trim `\x00` then whitespace |
| 36 | 4 | SchemaVersion | uint32; always **1** |
| 40 | 8 | CreatedDate | uint64 Unix **milliseconds** |
| 48 | 8 | SequenceNumber | int64 |
| 56 | 8 | Flags | uint64; bit 0 SYN, bit 1 FIN |
| 64 | 16 | MessageId | UUID stored **least-significant 8 bytes first** (`uuid[8:16]` at 64, `uuid[0:8]` at 72) |
| 80 | 32 | PayloadDigest | SHA-256 of Payload |
| 112 | 4 | PayloadType | uint32 (table above) |
| 116 | 4 | PayloadLength | uint32 |
| 120 | n | Payload | bytes |

`Validate`: returns nil early for `start_publication` / `pause_publication`; otherwise requires `HeaderLength != 0`, `MessageType != ""`, `CreatedDate != 0`; when `PayloadLength != 0` the SHA-256 of `Payload` must equal `PayloadDigest` (error text `payload Hash is not valid`). Harbormaster's `Deserialize` additionally rejects `len(b) < 120`, `HeaderLength != 116`, and `PayloadLength != len(b) - HeaderLength - 4`.

### Task 2: Data channel: sequence numbers, acks, retransmission, reorder, handshake

**Files:**
- Create: `internal/execbridge/datachannel.go`, `internal/execbridge/datachannel_test.go`

**Interfaces:**
- Consumes: Task 1 types and constructors.
- Produces:
  - `type FrameConn interface { ReadFrame(ctx context.Context) (text bool, data []byte, err error); WriteBinary(ctx context.Context, b []byte) error; WriteText(ctx context.Context, b []byte) error; Close() error }` — writes are safe for concurrent use by the implementation.
  - `type EventKind uint8` with `EventOutput` (Data = payload bytes, PayloadType Output or StdErr), `EventExitCode` (Data = raw payload), `EventHandshakeComplete`, `EventChannelClosed` (Closed set), `EventError` (Err set; channel is dead).
  - `type Event struct { Kind EventKind; PayloadType PayloadType; Data []byte; Closed ChannelClosed; Err error }`
  - `type DataChannelConfig struct { ClientID, Token, ClientVersion string; ResendInterval time.Duration; ResendMaxAttempts int; InitialRTO, MaxRTO time.Duration; OutgoingCapacity, IncomingCapacity int; HandshakeTimeout time.Duration; Now func() time.Time; Logger *slog.Logger }` with `func DefaultConfig(clientID, token string) DataChannelConfig` filling the upstream constants below.
  - `func NewDataChannel(conn FrameConn, cfg DataChannelConfig) *DataChannel`
  - `func (d *DataChannel) Open(ctx context.Context) error` — sends the `OpenDataChannelInput` **text** frame (`MessageSchemaVersion "1.0"`, `RequestId` = new UUID string, `TokenValue`, `ClientId`, `ClientVersion`).
  - `func (d *DataChannel) Run(ctx context.Context) error` — read loop + resend scheduler; returns when ctx ends, the conn errors, or `channel_closed` was received; closes `Events()` on return.
  - `func (d *DataChannel) Events() <-chan Event` (buffered 256)
  - `func (d *DataChannel) SendInput(ctx context.Context, pt PayloadType, data []byte) error` — splits `data` into ≤1024-byte messages, one sequence number each; blocks while the outgoing buffer is at capacity (returns ctx error if ctx ends first).
  - `func (d *DataChannel) SendSize(ctx context.Context, cols, rows uint32) error` — `SizeData` JSON with `PayloadType Size`.

Rules to port:

1. **Outgoing (`input_stream_data`)**: `SequenceNumber` starts at 0 and increments per message sent successfully; `Flags` 0; a payload that is exactly the single byte `0x0A` is replaced by `0x0D` (upstream winpty quirk; keep). Each sent message is appended to the outgoing buffer with `LastSentTime` and `ResendAttempt`. Harbormaster change: at capacity, block the sender (upstream evicts the oldest).
2. **Resend scheduler**: every `ResendInterval`, look at the **oldest** unacknowledged message only; if `now - LastSentTime > RTO`, resend its exact bytes, update `LastSentTime` on the stored element (upstream updates a copy; fix that), increment attempts; when attempts reach `ResendMaxAttempts`, emit `EventError{Err: ErrResendTimeout}` and stop.
3. **Acknowledge received** (`acknowledge` from agent): parse `AcknowledgeContent`; remove the outgoing message whose `SequenceNumber` matches; update RTO: `RTTVar = (1-¼)·RTTVar + ¼·|RTT − sample|`, `RTT = (1-⅛)·RTT + ⅛·sample`, `RTO = min(RTT + max(ClockGranularity, 4·RTTVar), MaxRTO)`.
4. **Output received** (`output_stream_data`), with `expected` starting at 0:
   - `seq == expected`: for `HandshakeRequest`/`HandshakeComplete` payloads send the ack first, then process; for other payloads deliver, then ack; then `expected++` and drain the incoming buffer while `buffer[expected]` exists (deliver, `expected++`, no second ack).
   - `seq > expected`: ack it and store in the incoming buffer if below capacity (else neither).
   - `seq < expected`: duplicate; drop silently (no ack).
   - Flags on received messages are ignored.
5. **`start_publication` / `pause_publication`**: no-op (and `Validate` is skipped for them).
6. **`channel_closed`**: parse `ChannelClosed`, emit `EventChannelClosed`, return from `Run`.
7. **Handshake** (agent → client payload type 5 at seq 0): for each `RequestedClientAction`: `SessionType` → parse `SessionTypeRequest`; shell names above set session type `Standard_Stream`, `Port` is rejected (`ActionFailed`, error `port sessions are not supported`); `KMSEncryption` → `ActionFailed`, error `KMS-encrypted sessions are not supported by Harbormaster`; unknown → `ActionUnsupported`, error `Unsupported action <type>`. Reply with `HandshakeResponsePayload{ClientVersion, ProcessedClientActions, Errors}` as an input message with `PayloadType HandshakeResponse`. Then the agent sends payload type 7 (`HandshakeComplete`) → emit `EventHandshakeComplete` (its `CustomerMessage`, when non-empty, is forwarded as `EventOutput` text). Fallback kept from upstream `ProcessFirstMessage`: if the first message delivered is `Output` and no handshake happened, treat the session as a shell and emit `EventHandshakeComplete` before that output. If neither arrives within `HandshakeTimeout` (default 15 s) after `Open`, `Run` returns `ErrHandshakeTimeout`.
8. **Size**: `SizeData{cols,rows}` JSON as an input message with `PayloadType Size` (upstream sends it only when the size changed; the caller decides).
9. **Output payloads**: `Output` (1) and `StdErr` (11) are terminal bytes (upstream prints both to stdout); `ExitCode` (12) is surfaced as `EventExitCode`; `Error` (2) and others are logged at debug and dropped.

  - Route `GET /api/tasks/{taskId}/exec?container=<name>&command=<cmd>` upgraded with `websocket.Accept` (Origin check per plan 00). Cookie auth is checked by middleware before the upgrade (401 JSON). After the upgrade the **browser-side protocol** is:
    - Client → server, first frame within 5 s, text: `{"type":"start","csrf":"<token>","cols":120,"rows":32}`. Then text `{"type":"resize","cols":N,"rows":N}` and **binary** frames of raw input bytes.
    - Server → client: text `{"type":"status","state":"connecting"}` immediately after a valid start; `{"type":"status","state":"connected","session_id":"ecs-execute-command-…"}` after the handshake; `{"type":"status","state":"closed","reason":"<CloseReason>","session_id":"…","duration_ms":N}` before closing normally; `{"type":"error","code":"<code>","message":"<sentence>"}` before an error close. **Binary** frames carry output bytes.
    - Close codes (constants in `exec_ws.go`): `1000` normal; `4400` `bad_request` (missing/late/malformed start, unknown message type); `4401` `csrf_invalid`; `4404` `not_found` (task invisible, not RUNNING, unknown container); `4409` with codes `exec_disabled` ("ECS Exec is off for <service>."), `agent_not_running` ("The ExecuteCommandAgent is not running in container <name>."), `session_limit` ("You already have 3 open terminal sessions."), `invalid_command` ("Command must be /bin/sh or /bin/bash."); `4408` `idle_timeout`; `4410` `max_duration`; `4502` `aws_error` (ExecuteCommand or SSM failure; message = AWS error message or "SSM session ended unexpectedly.").
  - Permission: `authz.Can(subject, authz.Terminal, TaskTag(...))`. A subject without View on the tag gets `4404 not_found` (the task is invisible). A subject with View but without Terminal already sees the task, so hiding it reveals nothing: answer `4409` with the error frame code `forbidden` (00 §api: visible resource, missing action) and message "You need Terminal on <tag> to open a terminal." (the UI shows the lock panel; this is the server-side guard, spec §1.5). Every HTTP response of this plan follows 00: invisible → 404 `not_found`, visible without the action → 403 `forbidden` (`forbiddenAction`); `exec-targets` reports the missing action as `can_terminal: false` instead.
  - Operations log (`store.AppendOperation(store.Operation{AccountID, Region, Cluster: t.Cluster.Cluster, Service: &t.ServiceName or nil for standalone, ActorUserID: &subj.UserID, Source: "harbormaster", …})`): on `connected`: text `Opened terminal session on task <first 12 chars of task id> (<container>, <command>).`, details `{"task_arn","container","command","session_id"}`; on close: text `Closed terminal session on task <12> (<container>) after <Nm Ns>.` with details adding `{"duration_ms","reason"}`. Format `<Nm Ns>` as `4m 12s`, `0m 07s` → `7s`, `1h 02m 05s` for ≥ 1 h.
  - Lifecycle: `Limiter.Acquire(userID)` before `ExecuteCommand`, released on close; `Session.Close(CloseByClient)` when the browser socket closes or errors; `Session` events pumped to the socket; browser binary frames → `Session.Write`; resize → `Session.Resize`.
