# Harbormaster 03: Observe (metrics, logs, scaling, alerts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add everything a user looks at but never changes: CloudWatch metrics (Container Insights, ALB) on every page, CloudWatch Logs history and live tail, the read-only Scaling tab, and the alert table with "Needs attention".

**Architecture:** `internal/metrics` is a namespace-agnostic `GetMetricData` client (≤500 queries per call, `NextToken` paging) in front of a Postgres `metrics_cache` with a 60 s TTL shared by every Harbormaster task; builders turn cluster/service/task/target-group identifiers into query sets and pure derivations turn raw series into what panels show. Two new poller tiers (target health 15 s, auto scaling 60 s) and one DB-only tier (alert evaluation 5 s) keep `target_health`, `scaling`, `service_status_runs` and `alerts` current; `internal/status/alerts.go` is pure and table-tested. `internal/logs` wraps `FilterLogEvents` (backwards paging, 500 lines) and `StartLiveTail` (relayed over a coder/websocket connection with a per-user limiter and a 30-minute idle stop). The API adds read endpoints guarded by View (metrics, scaling, alerts, target health, deployments) and Logs (history, tail), and the React app adds the chart panels, the Metrics/Scaling/Logs tabs and the banners.

**Tech Stack:** Go 1.26, AWS SDK for Go v2 (`service/cloudwatch`, `service/cloudwatchlogs`, `service/elasticloadbalancingv2`, `service/applicationautoscaling`), pgx v5, `github.com/coder/websocket`, `log/slog`; React 19 + TypeScript, TanStack Query v5, Vitest + Testing Library, Playwright.

**Spec:** [`docs/design/2026-10-31-harbormaster-design.md`](../../design/2026-10-31-harbormaster-design.md) — §5.1 (Auto scaling, Metrics, Target health rows), §5.2 (counts history is 01's; used here), §6.0 (≤ 8 series), §6.1–6.3 (chart panels), §6.4 Overview/Metrics/Scaling/Logs tabs, §6.12 alerts, §8 logs, §13 endpoints, §14 (60 s refetch on metrics), §17 phase 3. Shared conventions: [`2026-10-31-00-conventions.md`](2026-10-31-00-conventions.md) (read first). Mockup: `docs/design/mockup/index.html` (functions `vOverview`, `vClusters`, `vCluster`, `sOverview`, `sMetrics`, `sScaling`, `sLogs`, `alerts`, `chart`/`vbars`/`spark`/`donut`/`deployTimeline`); screenshots `docs/design/screens/{overview,clusters,cluster,service-overview,service-metrics,service-scaling,service-logs}.png`.

- Spec §6.0: multi-line charts never draw more than **8** series: top **7** by the plotted value plus **"others"**.
- Spec §6.4 Metrics tab ranges **1 h / 6 h / 24 h / 72 h**; without Container Insights "a banner explaining how to enable it in Terraform, no empty charts".
- Spec §8, verbatim: history newest **500** lines first, "load older" pages backwards; stream names `<prefix>/<container>/<task-id>`; live tail stops when the tab closes or after **30 minutes idle** (resumable); at most **2** concurrent live tails per user; warnings/errors filter is a client-side heuristic on `WARN`, `ERROR`, `FATAL`, `level=error`, JSON `"level":"error"`; non-`awslogs` containers: name the driver and say Harbormaster cannot show those logs.
- Spec §6.12 alert table (conditions and severities are copied into Task 7 verbatim). Spec §3 rule 4: invisible services appear in no alert, chart or count.
- Spec §14: metrics queries refetch every **60 s**; live pages every 5 s; paused when the tab is hidden. Charts are fixed-height panels (80–220 px) with HTML labels, 1.4 px lines, deployment markers — reuse plan 01's `web/src/charts/*` unchanged.
- Permissions: metrics, scaling, alerts, target health and deployments need **View** on the effective tag (else 404 `not_found`); logs history and tail need **Logs** (no View → 404; View without Logs → 403 `forbidden` with message `You need Logs on {tag}`, matching plan 02's convention for a missing action on a visible service).
- Interval, TTL and limit values are configuration (`HM_` vars named in Task 2) with the spec values as defaults; poll intervals follow 01's `Poll.*` / `HM_POLL_*` naming.

## Review Focus

1. A service attached to **two target groups** (two listeners or two load balancers): ALB panels must sum `RequestCount` and 5xx across groups, average p95, and the target health donut must count every group — not silently show the first. Test `TestALBQueries_TwoTargetGroups` (Task 4) and `TestTargetHealthLoop_TwoGroupsOneService` (Task 5).
2. **Container name that is a prefix of another** (`api`, `api-sidecar`): the history and tail stream prefix must be `<prefix>/<container>/` with the trailing slash, otherwise `api` returns the sidecar's lines. Test `TestStreamPrefixes_TrailingSlash` (Task 11).
3. **CloudWatch throttling or outage with a warm cache**: the page must keep showing the last series marked stale with the AWS message, not go blank; with a cold cache it answers 503 `throttled` / 502 `aws_error`. Tests `TestFetch_StaleOnThrottleWithCache`, `TestFetch_ThrottleWithoutCacheReturnsThrottleErr` (Task 3).
4. **Scaled-to-0 service or a cluster that just enabled Insights**: CloudWatch returns no datapoints; series must be all-`null` and the UI must say "No data yet" in the panel rather than draw a flat 0 % line. Tests `TestFetch_NoDatapointsGivesNulls` (Task 3) and `renders No data yet when every value is null` (Task 20).
5. **Search text with CloudWatch filter-pattern metacharacters** (`"`, `?`, `*`, `[`, `{`, a leading `-`): plain terms must be quoted and escaped so a user searching `error "db"` or `[warn]` gets matches, never an `InvalidParameterException`. Test `TestFilterPattern_EscapesMetacharacters` (Task 11).

  ```go
  type Dim struct{ Name, Value string }
  type Query struct {
      ID         string   // result id, CloudWatch-legal: ^[a-z][a-zA-Z0-9_]*$; unique within a Fetch
      Namespace  string   // "ECS/ContainerInsights" | "AWS/ApplicationELB" | "AWS/EFS" (05) | ...
      MetricName string
      Dimensions []Dim    // order as given; CacheKey sorts a copy
      Stat       string   // "Average" | "Sum" | "Maximum" | "SampleCount" | "p95" (ExtendedStatistic when it starts with "p")
      Period     int      // seconds, multiple of 60
      Label      string   // free text carried to Series.Label
  }
  type Span time.Duration  // how far back from now; helpers below
  const ( Span1h = Span(time.Hour); Span6h = Span(6*time.Hour); Span24h = Span(24*time.Hour); Span72h = Span(72*time.Hour) )
  func ParseRange(s string) (Span, bool)       // "1h"|"6h"|"24h"|"72h"
  func DefaultPeriod(s Span) int               // 1h→60, 6h→300, 24h→1200, 72h→3600 (≈60–72 points); other spans: smallest multiple of 60 giving ≤ 100 points, min 60
  type Series struct{ ID, Label string; Values []*float64 }     // one entry per grid bucket; nil = no datapoint
  type Result struct {
      Start, End time.Time; Period int        // End = floor(now, period); Start = End − span rounded up to whole periods
      Timestamps []time.Time                  // bucket starts, ascending, len == len(Series[i].Values)
      Series     []Series                     // in query order
      FetchedAt  time.Time
      Stale      bool; StaleReason string     // served from an expired cache row because CloudWatch failed
  }
  type Point struct{ T time.Time; V *float64 }
  func (r *Result) Points(id string) []Point     // the series with that ID zipped with Timestamps (plan 05 consumes this form); nil when unknown
  func CacheKey(t awsx.Target, span Span, period int, q Query) string   // sha256 hex of a canonical JSON {acct,region,span,period,ns,metric,dims(sorted),stat}
  type Client struct{ Clients awsx.Clients; Store *store.Store; TTL time.Duration; MaxStale time.Duration; Now func() time.Time; Log *slog.Logger }
  func New(c awsx.Clients, s *store.Store, ttl time.Duration) *Client    // MaxStale = 10 min, Now = time.Now
  func (c *Client) Fetch(ctx context.Context, t awsx.Target, span Span, queries []Query) (*Result, error)
  ```

If CloudWatch fails: when **every** uncached query has a cache row younger than `MaxStale`, return those with `Stale true`, `StaleReason` = the AWS error message (throttled → `"CloudWatch is throttling requests"`); otherwise return the error unchanged (the API maps `awsx.IsThrottle` → 503, else 502). Partial failure of one chunk fails the whole Fetch (simple, rare). Period must be identical across queries of one Fetch (`ErrMixedPeriods`); callers needing another period (the 5xx-per-hour bars) call Fetch twice.
