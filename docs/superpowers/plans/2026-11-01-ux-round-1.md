# UX Round 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every screen full-width and full-height, add an app-wide tag filter, show only what needs attention (Task health list, alerts that clear, stopped tasks within a configurable window) and fold the four admin pages into one Settings page.

**Architecture:** The tag filter rides on the store's existing `Visibility` mechanism: `scopeFrom` narrows `Vis.TagIDs` to the requested tags (admins become a non-admin visibility over those tags), so every list, count and summary that already applies `Visibility` in SQL filters by tag with no new queries. Alerts keep their 5 s tier; only the `status` package's window rules change. The stopped-task window is a `TaskQuery.StoppedAfter` cutoff set by the API from a new `settings` key/value table (migration `0060`); the poller never sets it, so alert inputs and the 72 h summary are untouched. The SPA extends `Filters`/`useFilters` with `tag: number[]`, adds a `MultiSelect` control, a Clusters filter bar whose account/region/tag state *is* `useFilters`, and a `/settings/:tab` page that hosts the existing admin components as tab panels.

**Tech Stack:** Go 1.26, pgx v5, `net/http` ServeMux; React 19 + TypeScript, react-router, TanStack Query v5, CSS modules, Vitest + Testing Library + MSW, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-01-ux-round-1-design.md` (binding). Conventions: `docs/superpowers/plans/2026-10-31-00-conventions.md` (every line of its "Global constraints" applies).

## Decisions (rulings the implementer must not re-decide)

1. **Tag filter mechanics (backend):** `scope` gains `TagFilter []authz.TagID` and `scopeFrom` narrows `Vis` with `narrowVisibility`. No store signature changes. `getAlerts` additionally checks the service alert's effective tag against `TagFilter` (service alerts bypass `Vis`). `/api/poller`, `/api/me`, admin endpoints and detail endpoints (`/api/clusters/{id}`, `/api/services/{id}`, `/api/tasks/{id}/*`) are unaffected because the SPA never sends `tag` to them.
2. **Tag filter mechanics (frontend):** `Filters` gets `tag?: number[]` (named after the URL param); `queryString` learns arrays (repeated key). Stored in localStorage next to `account`/`region`. Visible tag ids for a user = all `me.tags` for admins, else ids whose `me.perms[id]` has the View bit (`VIEW_BIT` in `web/src/app/admin/perms.ts`).
3. **Search** (`/api/search`) is one of the places "where account and region apply"; the SPA currently sends neither. `useSearch(q, filters)` now sends account, region and tag.
4. **`deployment_failed` stale rule:** with `newest` = newest deployment by `CreatedAt`, the alert is suppressed when `svc.Running >= svc.Desired`, no deployment is `IN_PROGRESS`, and some deployment with `Status == "PRIMARY"` has `Running >= svc.Desired`. A PRIMARY FAILED deployment with `Running: 0` while old ACTIVE tasks keep the count up is **not** steady (the existing table case stays red). The 24 h cap stays as the outer bound.
5. **Seed changes (Task 1):** service override `ci-tools/artifact-proxy → Prod` (cluster stays Dev; demonstrates the owner's example); image-resizer's six OOM stops move from `(i*3.5 + 0.3) h` ago to `(i*12 + 4) min` ago (4, 16, 28, 40, 52, 64 min), so one stop is inside the 10-minute window, five are inside the 1-hour restart-loop window, all six stay inside 72 h. No other estate numbers change.
6. **Settings storage:** key/value table `settings(key text primary key, value text not null, updated_at timestamptz not null)`; one key `stopped_tasks_window_minutes`; absent row = default 10. Validation (1–1440) lives in the API handler (422 `invalid`).
7. **Window predicate:** `TaskQuery.StoppedAfter time.Time` (zero = no window) adds `(t.last_status is distinct from 'STOPPED' or t.stopped_at >= $cutoff)` to `ListTasks`; `tasksList` sets it to `now − window` for the page query and all four count probes. Both task lists the SPA has (`GET /api/tasks`, the "cluster's tasks" being that list scoped by account/region/cluster, and `GET /api/services/{id}/tasks`) go through `tasksList`, so one change covers the spec's three places; `serviceTasks` in `services.go` (running tasks for the service DTO) and the poller leave `StoppedAfter` zero.
8. **Task health bars:** stacked parts to `desired`: healthy (`running − unhealthy − rolling_out`, `var(--success)`), unhealthy (`var(--warning)`), rolling_out (`var(--info)`), missing (`var(--danger)`); label `running / desired`; `ghost` = desired. Listed only when `unhealthy + rolling_out + missing > 0`; otherwise the muted line "All clusters healthy".
9. **Grids:** stat grids (`.g4`, `.g3`, `.g2`, tasks `.grid`, MetricPanels `.g3`) become `repeat(auto-fit, minmax(<min>, 1fr))` so a few tiles stretch instead of leaving empty columns (anti-goal 4); card lists (`.cards`, `.netCards`) stay `auto-fill`. Minimums: tiles 240px, 3-up cards 320px, 2-up 360px. `.gWide` (2fr/1fr) keeps its media query. The old `.g4`/`.g3` media queries are deleted.
10. **Panel heights:** `ServicePage` wraps the tab body in `<div className={styles.tabPanel}>` (`flex: 1 1 auto; min-height: 0; display: flex; flex-direction: column`); LogsTab's root and TerminalTab's root become flex columns; `.logs` and `.term` use `flex: 1 1 auto; min-height: 320px` (no `height`). `TaskTerminal` (standalone page) applies the same rule to its terminal host. The task-definition diff is inside `ReviewDialog` (a dialog keeps its width) but its cap becomes viewport-relative: `max-height: max(380px, 70dvh)`. Since `.content` is already `flex: 1; overflow: auto`, nothing caps width today; Task 7 asserts that with an e2e measurement instead of changing more CSS.
11. **Cluster filter bar:** status as four toggle buttons (`aria-pressed`) in `role="group" aria-label="Status filter"`, labels from `clusterStatusLabel`; name search `<input type="search" aria-label="Cluster name">`; account/region/tag rendered by the shared `Filters` component with `variant="page"` (aria-labels "Account", "Region", "Tags" so they never collide with the top bar's "Account filter"/"Region filter"/"Tag filter"). "Clear filters" clears all five. URL params `status` (repeated) and `q`.
12. **Settings page structure:** `web/src/app/settings/SettingsPage.tsx` owns crumbs, the `AdminOnly` guard and the `Tabs`; `Tags`, `Users`, `Accounts`, `Audit` stay in `web/src/app/admin/*` but become panels: no `useCrumbs`, no `AdminOnly`, their `<h1>` becomes `<h2>`. The sidebar keeps the "Admin" section heading with one entry "Settings" → `/settings/general`. `AdminOnly` gains area `general` with copy "Only global admins change settings."
13. **Alert copy:** restart loop text becomes "{n} tasks stopped with an error in the last hour."
