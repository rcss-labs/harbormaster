# Harbormaster 01: Foundation, read-only — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Implementer tiers:** tasks are implemented by subagents. Each task carries an `Implementer:` line — **Haiku** for mechanical/scaffolding work, **Sonnet** for hard logic (poller, auth, authz, store queries, API, shell). Escalate one tier when a task fails twice.

**Goal:** A deployable Go binary + React SPA that signs users in, polls ECS across accounts and regions into Postgres, and shows Overview, Clusters, Cluster, Service (overview/tasks/operations), Tasks and the admin screens, with permission filtering on every endpoint — read-only (spec §17 phase 1).

**Architecture:** One Go binary: `api` serves the embedded SPA and JSON from Postgres snapshots; `poller` (leader only, advisory lock) copies ECS state into snapshot tables on a tiered schedule; `authz` is a pure permission engine over Harbormaster-internal tags; `awsx` hides AWS behind narrow interfaces so `awsx/fake` can drive the whole product (`serve --fake-aws`). The SPA refetches every 5 s with ETag/304.

**Tech Stack:** Go 1.26, AWS SDK v2, pgx v5, slog, `net/http` ServeMux; React 19 + TypeScript + Vite, react-router, TanStack Query v5, Vitest + Testing Library + MSW, Playwright; PostgreSQL 16.

**Spec:** [`docs/design/2026-10-31-harbormaster-design.md`](../../design/2026-10-31-harbormaster-design.md) · **Conventions:** [`2026-10-31-00-conventions.md`](2026-10-31-00-conventions.md) (read first; every type named there is used unchanged) · **Mockup:** [`docs/design/mockup/index.html`](../../design/mockup/index.html) (line numbers below refer to it) · **Screens:** [`docs/design/screens/`](../../design/screens/)

## Global Constraints

- Everything in 00 "Global constraints" applies: Go 1.26, module `github.com/rcss-labs/harbormaster`, pgx v5, slog, ServeMux patterns, React 19/Vite/TanStack Query v5, Node ≥ 22, PostgreSQL 16, SQL migrations `internal/store/migrations/NNNN_name.up.sql`, MIT, no Stackstead code, `HM_` env vars only, all AWS through `internal/awsx`, DB tests via `HM_TEST_DATABASE_URL` (skip when unset), full-width layout, conventional commits, TDD, `gofmt`/`go vet`/`npm run lint`/`npm run typecheck` before every commit.
- Vite `build.outDir` is `../internal/web/dist`; `internal/web/dist/` is git-ignored except a committed placeholder `index.html` (00).
- Snapshot freshness (00): cache rows' `polled_at` = when their content last changed; unchanged rows are never rewritten; "data as of" comes from `poll_loops(account_id, region, tier, last_ok_at, last_error, interval_ms)` updated once per loop cycle.
- Pinned store API from 00 is implemented here with exactly those names: `GetService`, `GetTask`, `GetTaskDefinition`, `UpsertTaskDefinition`, `Operation`, `AppendOperation`, `ListOperations`. 01's poller only **inserts** `deployment_history` rows (`kind='deploy'`, `outcome NULL`); plan 02 owns outcomes.
- Passwords: argon2id, memory 64 MiB, iterations 3, parallelism 2, 16-byte salt; minimum length 12 (spec §10).
- Sessions: random 32-byte ID, cookie `hm_session` `HttpOnly; Secure; SameSite=Lax`, stored hashed; idle expiry 12 h, absolute 7 days (§10).
- Brute force: 5 failed attempts per username per 15 min → username locked 15 min; 30 attempts per IP per 15 min; failed attempts audited; error is always "Wrong username or password." (§10, §6.11).
- Usernames: 2–32 chars `[a-z][a-z0-9._-]{1,31}` (§6.8). Tag names: 1–24 chars, start with a letter, unique case-insensitively; colours `neutral|red|amber|blue|violet|green`; `Dev` built in, cannot be renamed or deleted (§6.9).
- Permissions: `V=1 L=2 O=4 D=8 E=16 T=32`; every action requires View; presets None/Viewer/Operator/Deployer/Full, else "Custom" (§3). Resources the user has no View on return **404**; a visible resource whose action the user lacks returns **403** `forbidden` with a message naming it ("You need Deploy on Prod") — this plan only has read endpoints, so 403 is used for admin areas here and the helper `forbiddenAction(action, tagName)` is defined for plans 02–04 (00 §api). At least one global admin always exists (§3).
- Effective tag: service's own tag, else cluster's tag, else Dev. Standalone tasks use the cluster's tag (§2, §3.7). Cluster visible when ≥1 of its services is visible (§3.5); admins also see empty clusters.
- Poll intervals (defaults, all configurable, §5.3): DescribeServices 5 s, ListTasks RUNNING 5 s, full DescribeTasks 30 s, ListTasks STOPPED 15 s, ListClusters/DescribeClusters 60 s, ListServices 60 s; counts history every 5 min. ±500 ms jitter, 8 in-flight calls per loop. Throttle: tier interval ×2 (max 60 s), halve after 5 clean cycles. 3 consecutive failures → loop marked failing.
- Retention (§12): stopped tasks 7 d, service events 30 d, counts history 7 d, operation log 90 d, deployment history 90 d, audit 1 y, orphaned tag assignments 30 d, expired sessions immediately; job runs hourly on the leader.
- STS: `AssumeRole` with external ID (24 random chars), session name `harbormaster`, 1 h duration, refresh 5 min before expiry (§11.1).
- Scale rules (§6.0): lists paginated server-side (default page 100, max 500); clusters page defaults to table when > 30 clusters match; charts never draw > 8 series.
- API shapes per 00: error body `{"error":{"code","message"}}`, list body `{"items","next","polled_at"}`, `ETag`/`If-None-Match` → 304, CSRF header `X-CSRF-Token` on every non-GET.
- Extra error code this plan adds: `password_change_required` (403) for any API call other than `/api/me`, `/api/auth/password`, `/api/auth/logout` while `users.must_change_password` is true.

## Review Focus

1. **Same-named services in two clusters (legacy short ARNs)** — both stay distinct, keep their own tags and counts. Test: Task 7 `TestUpsertServices_SameNameDifferentClustersStayDistinct`.
2. **Standalone tasks (no service)** — appear on the Tasks page under the cluster's tag, grouped by `group`/`startedBy`; a user with View on that cluster's tag sees them, others get nothing. Tests: Task 9 `TestEffectiveTaskTag_StandaloneUsesClusterTag`, Task 19 `TestTasks_StandaloneVisibleByClusterTag`.
3. **AWS pagination and batch limits** — ListTasks pages of 100, DescribeTasks ≤100 ARNs, DescribeServices ≤10 names, ListServices pages; a cluster with 250 running tasks must be fully described. Test: Task 14 `TestLoop_RunningTasks_PaginatesAndChunks`.
4. **User deleted or de-admined while signed in** — next request is 401 (sessions ended) / 403 for admin areas. Tests: Task 16 `TestDeleteUser_EndsSessions`, Task 20 `TestRemoveAdmin_EndsSessionsOfThatUser`.
5. **Remembered account/region filter pointing at an account that was disconnected** — the shell falls back to "All" instead of an empty screen. Test: Task 28 `Shell.test.tsx › "falls back to All when the stored account no longer exists"`.
