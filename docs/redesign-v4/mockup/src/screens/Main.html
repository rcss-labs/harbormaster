Keep the density. Make the next action obvious, and stop the chrome competing with the work.

The current UI is already dense and capable, so this proposal does not start again. It keeps the brand, the vocabulary and every capability, and changes the layout, navigation, failure handling and legibility that got in the way when we ran the app.

What we reviewed

We built the current main branch and ran it through its real AWS code path against the floci emulator (ECS, EC2, EFS, ELB v2, Logs, STS), with 9 services in 6 clusters across 3 regions, and captured every route at 1440 × 900. A code inventory of every page, column, dialog and message set the scope of the mockup.

Limits: floci returns no Container Insights metrics, so charts were sparse and chart craft was judged from the code and earlier screenshots. It also does not implement DescribeScheduledActions. That gap triggered findings 1 and 4, but any denied or failing AWS call in production takes the same code path.
